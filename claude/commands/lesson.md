Look back over this session for what would save a future session real time:
- Where the user corrected you or repeated an instruction.
- Wrong approaches you pursued and then dropped.
- Commands that failed for a reason you had to work out.
- Facts about a tool or data source that surprised you.

$ARGUMENTS

Sort each one:

1. **Specific to this project** (a data quirk, a domain fact): add it to the project's `AGENTS.md`,
   as part of your PR.
2. **Would hold in an unrelated project:** run `study-kit lesson "<text>"`, one call per lesson.
   Phrase the rule so it doesn't depend on this domain, then give the concrete evidence in
   parentheses: what happened, with the numbers or error text. Leave out private details.
3. **Neither:** drop it. One-off mistakes and obvious facts don't earn an entry. If nothing
   qualifies, say so.

Never edit the global lesson list, and don't read the inbox. Then tell the user what you saved and
where.
